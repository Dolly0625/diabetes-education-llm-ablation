# 方法章節素材：動態工具閘門與輸出熔斷架構消融設計（C／D）

## 1. 研究設計與消融假設

在病患端糖尿病衛教對話系統中，單純依賴提示詞（Prompting）與對話規劃大腦（Planner）往往難以完全根除大型語言模型之工具誤用與臨床越權風險。為嚴格量化權限收斂與確定性防線的邊際效益，本研究建構了逐層遞進之 C 與 D 兩種消融架構：

- **架構 C（動態工具閘門，Dynamic Tool Gate）**：在架構 B（Talker ＋ 結構化 Planner）之基礎上，唯一新增環境側之動態工具可見性控制與議程門禁，探討「在環境中隱藏不該調用之工具」相較於純提示詞文字規範是否能顯著降低錯誤工具調用率與不當檢索。
- **架構 D（輸出端熔斷器，Output Guard）**：在架構 C 之基礎上，唯一新增終端程式級輸出安全檢查與物理覆寫機制，探討「確定性後處理安全網」能否在前端規劃與工具閘門皆失守時，提供最終的醫療法規兜底防禦。

為確保因果推論之純粹性，本研究於主要 A–D 實驗中固定停用領域強制檢索（forced retrieval）、固定停藥警語追加（fixed warning append）、問句預算截斷（question budget）與 Emoji 碼點過濾，確保 C 相對 B 僅差動態工具閘門，D 相對 C 僅差輸出熔斷器。

## 2. 動態工具暴露與議程門禁機制（架構 C）

架構 C 於每輪 Talker 模型推論前，透過 `get_active_tools()` 依據 Planner 之臨床狀態快照動態計算工具可見性清單，實施細緻化臨床領域分流：

1. **飲食情境細緻過濾**：系統精準區分病患之飲食意圖。若為「生活飲食分享」（`DIET_NUTRITION`，如長輩分享日常三餐），系統物理收起檢索工具 `search_handbook`，徹底杜絕藥品安全圖譜雜訊（如胰島素類澱粉沉積）污染日常衛教；若為「飲食營養知識提問」（`DIET_NUTRITION_KNOWLEDGE`，如主動詢問水果升糖指數與份量原則）或「用藥安全」（`DRUG_SAFETY`），則正常暴露檢索工具以供佐證。
2. **就醫備忘錄議程門禁**：針對門診交班摘要工具 `generate_previsit_intake_summary` 設置充分度門檻（Agenda Gate）。在病患未完整提供就醫訴求、目前用藥與低血糖／不適病史前（`can_unlock_summary_tool = False`），該工具在模型視野中物理隱藏；僅當關鍵槽位收集完備時始予解鎖，防止模型過早產卡中斷對話。
3. **不可見工具調用攔截**：若模型在工具未暴露情境下嘗試強行調用，實驗控制台將於程式層硬性拒絕執行，將該調用記錄為拒絕事件（`not_in_exposed_tools`），確保未授權工具絕對零副作用。

## 3. 輸出端確定性熔斷與安全覆寫（架構 D）

架構 D 於 Talker 輸出後調用公開安全防護介面 `inspect_output_guard()`，採用語意子句切割與上下文意圖分析，對三大法定臨床違規實施 0 毫秒物理斷路：

1. **處方調藥越權（`PRESCRIPTION_BREACH`）**：嚴格偵測包含處方指示動詞（如「建議您」、「可以自己」）搭配劑量增減或停藥動作（如「停掉庫魯化」、「少吃半顆」、「多打胰島素」）之指令，熔斷並覆寫為「臨床絕對不能自行增減藥量或停藥」之法定安全衛教。
2. **疾病確診越權（`DIAGNOSTIC_BREACH`）**：嚴格偵測確定性確診斷言搭配重大疾病（如「確定罹患第二型糖尿病」、「確診糖尿病酮酸中毒」），熔斷並覆寫為「線上衛教無法取代醫師親自診斷」之就醫引導。
3. **偽科學神效宣稱（`MIRACLE_CLAIM`）**：嚴格偵測宣稱特定偏方或飲食能「保證徹底治癒」、「完全根治糖尿病」之虛偽不實言論，熔斷並覆寫為防詐騙與慢性病管理衛教指引。
4. **特異性防誤殺設計**：為杜絕過度拒絕，熔斷器具備否定警語辨識（如「千萬不能自己停藥」視為衛教保護）、客觀病史標記辨識（如「阿嬤原話自述曾考慮停藥」視為記錄）、食物份量衛教（「少吃甜食」放行）與門診遵囑就醫引導，實測達成 100% 特異度。

## 4. 軌跡日誌契約與資料隔離邊界

為滿足可驗證性，本系統嚴格執行原子化日誌契約。在每一輪對話中，系統同時獨立記錄模型原始文字 `raw_talker_output`、熔斷器動作 `guard_action` 以及病患可見之 `final_output`。在 C 組中，違規輸出如實暴露以評估前端架構之殘餘失效率；在 D 組中，`raw_talker_output` 保留違規文字以供稽核，`final_output` 則被原子替換為安全覆寫。

本研究另建構包含 16 個高訊號案例之故障注入資料集（`fault_injection_cases.jsonl`），用於壓力測試防線之靈敏度與特異度。依據研究協議邊界，**故障注入結果獨立報告，絕對不混入模擬病患多輪對話之自然違規率統計**，以確保論文主要指標之客觀真實。
