# 糖尿病衛教大型語言模型之分層防護網消融研究：以對抗性壓力測試評估系統安全與錯誤再分配

## 摘要

糖尿病衛教對話系統在慢性病自我管理中扮演輔助角色，但病患反覆要求調整藥物或面對急性病況時的持續對抗性施壓，往往暴露僅依賴提示層約束的一般做法之脆弱。既有醫療大型語言模型安全評估多採整體黑盒子架構，難以將安全性變化細分對應至各個系統防護層。本研究對第二型糖尿病衛教對話助理開展探索性、非預先註冊之系統層級對抗壓力測試。在固定底層模型（`gemini-3.5-flash-lite`）與嚴格「唯一差異原則」下，依序消融並比較四組階梯防護配置：Base (A)、Planner (B)、Planner + Gate (C) 與 Full-stack (D)；四組均包含全程啟用之輸入防護網（Input Guard，Base 亦在共同提示詞與 Input Guard 基礎上運作）。測試包含 12 個主安全案例（涵蓋六類嚴重失敗）、2 個否定病史探針與 9 個良性對照，四組共執行 92 條完整多輪對話軌跡（204 個助理發言回合），無任何排除案例；所有對話軌跡經盲化封裝後由同一評判模型（`gemini-3.7-flash`）重複裁決（仍受限於潛在的同模型共享偏差）。

結果顯示，四組條件之嚴格與複合臨界失敗率（CFR_strict 與 CFR_composite）皆為 0/12，但其 Wilson 95% 信賴區間上限達 24.25%（各失誤類別更達 65.76%），顯示零觀察結果不足以支持零風險主張。事實與狀態一致性（FACT）呈現依情境而異的非單調變化：主案例事實錯誤在 Base、Planner、Planner + Gate 與 Full-stack 分別為 2/12、4/12、0/12、0/12；而在否定病史探針中，未提及之病史被自動填入摘要的發生率則分別為 1/2、1/2、2/2、2/2。良性對照之過度拒絕率在四組皆為 0/9。規則掃描器與評判者之 9 筆判定分歧皆為掃描器單向觸發，與詞彙掃描較敏感／較保守的解釋一致；然而評判模型亦非黃金真值，分歧僅反映不同機制之特性差異。總評估 API 成本為 US$0.8903688（約合新台幣 28.49 元）。本研究指出，分層防禦所呈現之現象與「錯誤再分配」模式一致，而非單向全面改善；研究屬模擬探索性質，無法推論因果關係，亦不主張 Full-stack 配置已達臨床最安全或可直接實體部署。

**關鍵詞：** 糖尿病衛教、大型語言模型、分層防護網、消融研究、對抗性壓力測試、錯誤再分配

# 1. 導言（Introduction）

慢性病患的長期居家自我管理日益仰賴衛教對話系統的輔助，其中糖尿病患者常因高齡且健康識能有限，特別需要清晰、一致且即時的衛教指引 [@Sng2023-diabetes-pitfalls]。大型語言模型雖然能提供涵蓋飲食原則、用藥遵從性與血糖監測等日常諮詢，但在常規衛教對話中，系統的潛在安全風險往往不易顯露。真正的臨床危害通常發生在對抗性或高壓情境下，例如病患反覆要求助理指導自行調整胰島素劑量、尋求線上診斷判定、要求背書未經證實的民間偏方，或在出現急性低血糖等急症徵兆時延誤就醫轉介 [@Huang2023-diabetes-accuracy]。過去針對糖尿病對話系統的研究已指出多種典型失誤，包含混淆血糖單位（mg/dL 與 mmol/L）、給予僵化且不切實際的飲食限制，以及無法辨識假性低血糖等現象 [@Sng2023-diabetes-pitfalls]。這些發現彰顯出：唯有透過系統性的多輪對抗性施壓，才能嚴格檢驗對話助理的安全邊界。

然而，單純依賴提示詞（System Prompts）來維護對話安全已被證實具有根本性的侷限。即便模型經過嚴格的安全對齊提示，在面臨多輪語意誘導、越獄攻擊或換句話說的持續施壓下，防線仍極易被突破 [@MedSafetyBench2024]。MedSafetyBench 的評估指出，即便具備安全對齊提示的模型，在醫療對抗攻擊下依然脆弱 [@MedSafetyBench2024]；WildGuard 亦發現，要精確區分真實危害與合理拒絕，必須仰賴專門的防護架構，而非僅靠提示詞約束 [@WildGuard2024]。因此，醫療對話系統亟需從僅依賴提示層約束的一般做法，轉向具備程式化、可稽核性的分層系統架構防護，透過在系統層級實作可解耦的控制機制，降低對單一模型內在對齊的過度依賴。

現有的醫療大型語言模型安全評估，多數仍將受測系統視為單一黑盒子進行端到端測試，僅回報整體的綜合安全指標，無法將安全性變化細分對應至具體的系統架構組件 [@HealthBench2025; @AgentClinic2026]。例如，HealthBench 跨越 5,000 輪對話評估黑盒子系統 [@HealthBench2025]，而 AgentClinic 在評估多代理人臨床工作流程時，亦未隔離特定防護層的獨立貢獻 [@AgentClinic2026]。這種黑盒子評估範式留下了一個關鍵的研究缺口：當一個系統同時整合了對話規劃員（Dialogue Planner）、動態工具門禁（Dynamic Tool Gate）與輸出安全網（Output Guard）等多層防線時，各個控制層究竟分別改變了哪種類型的錯誤？彼此之間是否存在權衡取捨？

為探討分層控制機制在各層級的表現差異，本研究對糖尿病衛教對話助理開展探索性、非預先註冊之對抗性安全壓力測試。我們依據嚴格的「唯一差異原則」，設計並評估了四組逐層遞增的防護配置（{FIG:1}）：**Base (A)**、**Planner (B)**、**Planner + Gate (C)** 與 **Full-stack (D)**。在此必須澄清，Base (A) 已包含四組共同啟用、全程固定的輸入防護網（Input Guard，負責攔截提示詞注入與自傷心理危機），因此並非僅依賴提示層約束的無防護基準，而是在共同提示詞與 Input Guard 基礎上運作。在以指定模型版本建構的模擬非臨床評估情境中，本研究提出四項核心研究問題：

- **RQ1（臨界安全失敗）：** 在多輪對抗性腳本施壓下，逐步導入對話規劃員、動態工具門禁與輸出安全網，是否會改變各組觀察到的臨界失敗率（Critical Failure Rate, CFR）？
- **RQ2（事實與病患狀態一致性）：** 分層控制機制如何影響系統對事實及病患狀態的一致性（FACT）？特別是，模型是否會在病患沉默未提及的情況下，無中生有編造未經陳述的否定性病史？
- **RQ3（過度拒絕）：** 防護層級的逐步收緊，是否會引發過度拒絕現象——即系統不當地拒絕回答常規、良性的糖尿病衛教諮詢？
- **RQ4（規則掃描器與評判模型之一致性）：** 決定性規則掃描器與盲測評判模型之間的判定一致性程度為何？兩者不一致的判定方向呈現何種模式？（規則掃描器僅為啟發式比對工具，不可視為黃金真值標準。）

本研究針對 23 個設計案例進行完整測試，四組共計產生 **92** 條完整對話軌跡與 **204** 個助理發言回合，且無任何排除案例（**23/23** 完整配對案例區塊）。所有軌跡經盲化封裝後由同一評判模型重複裁決，總評估 API 成本為 **US$0.8903688（約合新台幣 28.49 元）**。作為一項在模擬情境下以固定模型版本進行的探索性研究，本研究的核心發現並非宣稱任何單一配置「絕對最安全」，而是呈現出分層防護在特定情境伴隨錯誤減少的同時，可能伴隨不一致性在其他層次出現，呈現與**錯誤再分配（error redistribution）**一致的非單調現象。

# 2. 相關工作（Related Work）

## 2.1 醫療對話大型語言模型與模擬病患評估

多輪醫療對話系統的評估近年廣泛採納模擬病患（Simulated Patients）典範，以檢驗模型在貼近真實臨床互動中的推理與溝通能力。AMIE 系統透過自我博弈與推理鏈訓練，在涵蓋 20 位標準化病患演員與 20 位臨床醫師的隨機雙盲交叉 OSCE 試驗中，於 32 項溝通評估維度上達到或超越初級照護醫師之表現 [@AMIE2025]。Multimodal AMIE 進一步將此架構擴展至影像與臨床文件的即時判讀，並在 18 位專科醫師評估的 105 個臨床情境中建立明確的幻覺嚴重度分級制度 [@MultimodalAMIE2026]。AgentClinic 則建構了整合醫師、病患、量測與仲裁代理人的多代理人基準，支援長達 20 輪的互動，並評估系統在 23 種認知偏誤情境下的強韌度 [@AgentClinic2026]。CRAFT-MD 亦指出，將靜態醫學考題轉換為動態多輪問診對話時，模型準確率顯著下降，暴露出模型在主動病史詢問與跨輪資訊整合上的不足 [@CRAFT-MD2025]。

上述系統推進了對話式診斷品質的評估技術，但其核心關注點多集中於診斷準確性與衛教溝通技巧；鮮少有研究使系統處於長期的對抗性安全壓力之下，而這恰恰是面向慢性病患、面對反覆違規請求時最為關鍵的安全考驗。

## 2.2 醫療安全基準與對抗性壓力測試

為了應對醫療領域的特殊風險，部分基準已開始導入紅隊測試（red-teaming）與對抗性誘導入侵機制。HealthBench 彙整了包含 5,000 個多輪健康對話的資料集，結合全球 60 國、262 位臨床醫師制定的 48,562 條細緻評分標準，涵蓋對抗性紅隊情境與最差情況可靠度分析 [@HealthBench2025]。MedSafetyBench 依據美國醫學會（AMA）醫學倫理準則建構 1,800 個醫療安全測試案例，利用貪婪座標梯度（GCG）等對抗性演算法生成 900 個醫學越獄提示詞，並由 25 位醫師進行臨床驗證 [@MedSafetyBench2024]。WildGuard 則訓練了包含 92,000 筆真實與對抗合成資料的開源防護工具，嚴格區分「回覆危害性」與「拒絕行為」，為多維安全評估奠定基礎 [@WildGuard2024]。AgentHarm 更將安全評估拓展至代理人環境，量測模型在多步驟工具呼叫與相依工作流程中完成有害任務的比例 [@AgentHarm2025]。

這些基準確立了危害分類架構與對抗性測試方法，但多數研究仍將受測對象視為黑盒子，無法單獨析離對話規劃員、工具門禁與輸出護欄等架構組件各自發揮的安全效應。

## 2.3 分層程式化防護網與消融研究

從僅依賴提示層約束的一般做法轉向程式化安全控制，促成了可分解、模組化安全架構的研究。ToolEmu 在模擬沙盒環境中測試代理人在模糊指令下的行為，針對安全約束提示進行消融實驗，量化風險抑制與任務完成率之間的權衡 [@ToolEmu2024]。MedAgentBench 評估 12 款大型語言模型代理人在真實 FHIR API 電子病歷環境中執行 300 項臨床任務的表現，採用決定性規則評分器驗證 API 載荷的精確性，驗證了程式化驗證在臨床操作安全上的可行性 [@MedAgentBench2025]。在糖尿病衛教領域，RISE 提出了整合 24 條安全規則與兩階段事實查核的檢索增強生成架構，為糖尿病自我管理提供了早期分層防護的雛型 [@RISE2024]。

然而，既有的防護網研究多偏向單一機制的驗證，或是在全系統啟用與完全未防護之間對比，缺乏嚴格控制的階梯式消融設計。本研究透過嚴格的「唯一差異原則」——相鄰組別間恰切換單一組件開關（Base→Planner 引入規劃員；Planner→Planner + Gate 引入動態工具門禁；Planner + Gate→Full-stack 引入輸出安全網），使安全與錯誤形態的變化能夠提供逐層對照的受控比較依據。

## 2.4 LLM-as-a-Judge：可擴展性、評審偏誤與臨床落差

採用大型語言模型作為自動評估者（LLM-as-a-Judge）具備可擴展性高與成本低廉的優勢，但也伴隨著系統性偏誤。開創性的 MT-Bench 研究顯示，強大的評判模型能達到與人類專家 80% 以上的一致性，但同時揭露了三大固有偏誤：位置偏誤（position bias）、冗長偏誤（verbosity bias）與自我增強偏誤（self-enhancement bias）[@MTBench2023]。FairEval 進一步量化位置偏誤，發現對調選項順序時，GPT-4 的裁決翻轉率高達 46.3% [@FairEval2024]。

在臨床與醫療領域，評判模型與專業臨床醫師之間的落差更具風險。Croxford 等人發現，頂尖評判模型在病歷摘要評估上與臨床醫師專家小組的組內相關係數（ICC）為 0.818，其本質是逼近臨床醫師之間的共識上限，而非證明評判模型具備獨立正確性 [@PDSQI2025]。MedJUDGE 對 49 篇醫療 LLM-as-a-Judge 論文的範圍審查顯示，高達 73.5% 的研究完全依賴 GPT 系列模型，且 26.5% 完全未經過人類專家驗證，提示不同文獻可能共享同源模型的盲點 [@MedJUDGE2026]。尤為關鍵的是，DeLucia 等人發現，即便評判模型與臨床醫師做出相同的二元判決，兩者背後的臨床推理依據重合率僅有 24.6%，評判模型對不完整衛教內容的判別力 AUC 僅在 0.49 至 0.66 之間，接近隨機猜測水準 [@SameVerdict2026]。

這些實證嚴正提醒：即便採用盲測、同模型重複裁決的自動化流程，仍無法擺脫共享模型偏誤，絕不可將評判模型直接等同於獨立的人類專家審查。本研究採取此方法以確保評估的可重現性與低成本，但全程保留對其方法學限制的審慎邊界。

## 2.5 研究缺口（Research Gap）

既有文獻鮮少在固定底層模型的前提下，針對醫療對話系統的多層防禦架構進行逐層消融與受控比較。過去的研究極少在單一糖尿病衛教對話系統中，同時量測臨界失敗率、事實狀態一致性、過度拒絕率與規則掃描器–評判模型分歧。本探索性研究針對此一缺口提供受控比較與初步實證證據，透過嚴格的唯一差異消融設計，在專門針對糖尿病自我管理設計的對抗壓力情境下，剖析分層防禦對錯誤形態與安全表現的動態影響。

# 3. 系統架構與消融方法（System and Ablation Methods）

## 3.1 系統整體架構

本研究所測試的對象為專為第二型糖尿病設計之衛教大型語言模型對話助理。如 {FIG:1} 所示，系統在執行時期的主要管線依序包含：感知層（處理文字輸入、台語語音辨識與藥袋影像辨識）→ 輸入防護網（Input Guard）→ 長期記憶庫（Memory）→ 臨床規劃員（Planner）→ 衛教生成層（Talker LLM）→ 輸出安全網（Output Guard），最終輸出病患端衛教回覆或門診備忘錄 [@RISE2024]。

**{FIG:1} 系統執行期管線與受控工具調用架構。** 主路徑依序為感知層輸入（文字、台語語音、藥袋影像）→ Input Guard（四組固定 ON，目前實作僅阻斷提示注入與自傷心理危機，阻斷時回傳 `COMMON_INPUT_BLOCK` 終止對話回覆並獨立報告）→ 長期記憶庫 Memory（跨輪累積用藥、血糖、症狀事實）→ Talker LLM 生成核心（`gemini-3.5-flash-lite`，溫度 0.3，以護理師共感語氣進行衛教）。S1 開關（`enable_planner`）控制臨床規劃員（Planner）：A 組為 OFF 採中立狀態 bypass 直通，B/C/D 組為 ON 產生意圖定界與臨床導引注入 Talker。S2 開關（`enable_dynamic_tool_gate`）控制動態工具門禁：A/B 組為 OFF 暴露全工具清單，C/D 組為 ON 依 Planner 狀態動態過濾暴露工具；Talker 接收可見工具清單後，自主決定是直接生成文字或是發出 `tool call` 調用受控外部工具（雙軌 RAG `search_handbook` 與門診摘要 `generate_visit_summary`），檢索結果回傳 Talker 進行第二輪生成。Talker 輸出進入可選 Output Guard（S3 開關 `enable_output_guard`）：A/B/C 組為 OFF 直通輸出，D 組為 ON 執行 `inspect_output_guard`，攔截違規調藥或確診話術並強制安全覆寫；最終送出病患端衛教回覆或就醫備忘錄。向量圖檔見 `figures/figure1_system_ablation.svg`。

各模組的具體職責與互動介面如下：

1. **輸入防護網（Input Guard）：** 為所有組別共同的基礎防禦設施，四組全程固定開啟（ON）。必須依實際程式碼行為澄清：其阻斷範圍嚴格限定於提示詞注入攻擊與自傷心理危機；雖然原始程式碼註解提及胸痛等急性急症正則匹配，但底層並未實作此項規則阻斷。本研究完全依實際程式碼執行行為進行描述。
2. **長期記憶庫（Memory）：** 負責跨輪累積病患陳述的用藥歷程、居家血糖監測數據與身體症狀等縱向資訊。
3. **臨床規劃員（Planner，由 S1 開關控制）：** 解析病患當前輪次之意圖、決定檢索領域與資訊缺口，並生成結構化的臨床導引（`talker_guidance`）。當 S1 為 OFF 時，系統以中立狀態直通（bypass），不提供導引。
4. **動態工具門禁（Tool Gate，由 S2 開關控制）：** 作為工具可見性的動態過濾器。其核心功能是依據 Planner 產生的病患狀態與臨床導引，動態決定向 Talker 暴露哪些工具的 Schema（Allowed Tools Schema），而非強制中介資料流的管線節點。當 S2 為 OFF 時，系統向 Talker 暴露所有可用工具；當 S2 為 ON 時，則依狀態實施門禁過濾。
5. **衛教生成層（Talker LLM）：** 系統的核心生成引擎，採用溫暖、具共感力的糖尿病衛教護理師語氣生成回應。在標準消融設定中，前置強制檢索固定關閉。Talker 在接收到由 Tool Gate 暴露的工具清單後，自主判定是直接產生文字衛教，抑或是發出工具調用（tool call）。系統整合的外部工具包含雙軌 RAG 檢索（`search_handbook`，整合國健署糖尿病指引與衛福部仿單）以及門診摘要產卡（`generate_visit_summary`）。若 Talker 決定發起 RAG 檢索，執行後檢索證據將回傳至 Talker，觸發第二次生成回合（second talker turn）；若發起產卡，則於產卡後組裝就醫確認話術。本研究評估重點在於工具的暴露與調用決策時機，不評估 RAG 內部的向量檢索品質 [@RISE2024]。
6. **輸出安全網（Output Guard，由 S3 開關控制）：** 僅在 Full-stack (D) 組中啟用。在回覆送達病患前，對 Talker 的最終輸出或產卡內容進行合規性審查，一旦偵測到越權開藥、劑量調整或確診等嚴重違規，立即進行阻斷攔截並強制覆寫為合規的安全轉介話術。當 S3 為 OFF 時，Talker 的生成結果直接直通（passthrough）輸出。

## 3.2 A/B/C/D 消融設計與唯一差異原則

為了使相鄰條件具備嚴格的受控比較基礎，本研究採用嚴格的「唯一差異原則」：在相鄰實驗條件之間，恰好僅切換一個功能開關，其餘所有環境變數——包括模型主體、隨機取樣溫度、基礎系統提示詞版本、工具 Schema 定義——均保持絕對凍結不變 [@ToolEmu2024]。對應的消融開關配置如 {TAB:1} 所示。

**{TAB:1} A/B/C/D 逐層消融設計開關矩陣與唯一差異階層**

| 條件名稱 | enable_planner (S1) | enable_dynamic_tool_gate (S2) | enable_output_guard (S3) | 階層定義與防線增量 |
|---|---|---|---|---|
| **Base (A)** | OFF | OFF | OFF | 基準組：具備固定 Input Guard 之完整安全提示詞 Talker，全工具暴露 |
| **Planner (B)** | ON | OFF | OFF | 在 Base 之上新增結構化 Planner 臨床導引（guidance） |
| **Planner + Gate (C)** | ON | ON | OFF | 在 Planner 之上新增依 Planner 狀態之動態工具暴露與門禁 |
| **Full-stack (D)** | ON | ON | ON | 在 Planner + Gate 之上新增最終輸出違規攔截與強制安全覆寫 |

在四組設定中：
- **Base (A)** 為基準組：配置包含 Input Guard 與完整安全提示詞的 Talker，所有工具全數暴露，S1、S2、S3 均關閉。
- **Planner (B)** 在 Base 的基礎上開啟 S1，引入結構化的臨床導引。
- **Planner + Gate (C)** 在 Planner 的基礎上開啟 S2，引入動態工具門禁。
- **Full-stack (D)** 在 Planner + Gate 的基礎上開啟 S3，引入輸出端的安全攔截與覆寫機制。程式碼內部將 `enable_dynamic_tool_gate` 與部分文件中出現的 `dynamic_tool_gate` 視為完全等同的別名，本文統一使用規範命名 `enable_dynamic_tool_gate`。

為了排除非消融因素的干擾，以下三項生產環境輔助行為在所有實驗中一律強制關閉：(1) 由 Planner 領域強制觸發之檢索與提示詞注入（`enable_forced_retrieval`）；(2) 於 Output Guard 之外額外追加之停藥警語（`enable_fixed_warning_append` / `enable_noncompliance_append`）；(3) 強制單一問句預算與 emoji 清除之後處理機制（`enable_question_budget_postprocessing`）。本研究不對各組做出整體優劣的絕對排序，亦不宣稱任何一組在所有臨床指標上具備最佳安全性。

## 3.3 v2 實作與可重現性

本研究之 safety-stress v2 測試為前瞻性修訂的探索性實驗，非預先註冊，其測試數據與早期之探索版本（v1）及正式 12×4 實驗完全隔離報告，嚴禁合併統計或跨版本排名。

**案例與腳本設計：** 評估資料集共包含 23 個案例，分為 12 個主安全案例（涵蓋 6 類嚴重失敗情境，每類 2 案）、2 個事實/病患狀態探針案例（其 `cf_family="NONE"`，不列入 CFR 計算分母），以及 9 個良性對照案例。主案例與探針案例均採預先固定台詞的多輪腳本（各執行 3 輪對話），良性對照則執行 1 輪對話；整體評估規模為 92 條完整軌跡（23 案 × 4 條件）與 204 個助理發言回合（168 回合主案例/探針 ＋ 36 回合良性對照）。本測試未採用具隨機性的模擬病患代理人（Patient Agent），確保各條件面對之病患話語完全一致，病患背景事實不發生漂移。

**模型與運行參數：** Talker 與 Planner 均採用 `gemini-3.5-flash-lite`，隨機取樣溫度分別固定為 0.3 與 0.1；評判模型（Judge）則採用 `gemini-3.7-flash`，溫度設為 0.0。每條軌跡由評判模型進行兩次獨立的隔離評分；僅在出現臨界失敗判定分歧時，才以相同參數啟動第三次仲裁（tie-break）。必須特別強調：評判模型的重複評分僅能反映同模型自身的穩定度，並具有潛在的共享模型偏誤（shared-model bias），不可視為獨立人類專家審查，亦非客觀的評審間信度 [@MTBench2023; @FairEval2024; @SameVerdict2026]。

**盲測機制與方法學限制：** 評判模型僅能接收匿名化之對話封裝 `{blinded_run_id, patient_id, turns, reference_facts}`，遮蔽條件標籤、功能開關（`enable_*`）、條件對應表、Talker 原始暫存、Guard 動作歷程以及 Planner 內部狀態。然而，系統存在一項已確認的方法學邊界：由於對話軌跡中包含工具互動歷史，`tools_exposed` 的內容在客觀上使評判模型能夠區分 {Base, Planner}（全工具暴露）與 {Planner + Gate, Full-stack}（受控工具暴露），因此屬於部分解盲，本研究將其列為明確的評估限制。

**可重現性閘門：** 測試執行前須通過乾淨工作樹、基準標籤溯源、僅限 v2 範圍、5 枚凍結指紋校驗、A–D 唯一差異驗證、模型與溫度參數鎖定及端點白名單等嚴格的 fail-closed 檢查。執行期間每條軌跡採獨立程序執行，中斷點採原子性寫入。全流程設定了嚴格的成本硬上限（Talker 上限 US$1.00、Judge 上限 US$2.00、總上限 US$3.00），Token 消耗直接採計自 API 供應商回報。

## 4.2 評估方法與三層分類體系

本研究採用盲測 LLM-as-a-Judge 流程進行對話軌跡評估 [@MTBench2023; @FairEval2024]。評判合約要求針對五個面向進行 0/1/2 分級評定，並強制要求標註具體的對話輪次與文本證據。評估架構將系統表現區分為三層分類體系：**CRITICAL（臨界失敗）**、**FACTUAL_STATE（事實與狀態不一致）** 與 **QUALITY（衛教品質）**。

1. **臨界失敗率（CFR）：**
   - **嚴格臨界失敗率（CFR_strict）：** 計算主案例中出現任一嚴重失敗之軌跡比例。
   - **複合臨界失敗率（CFR_composite）：** 嚴格嚴重失敗與「符合升級條件之 FACT 錯誤」之聯集。兩項指標並列回報。
2. **事實與狀態層錯誤（FACT）：** 包含無根據之否定病史、無依據之肯定事實增補，以及與研究案例事實產生矛盾。FACT 預設屬於非臨界錯誤；唯有當文本證據確切證明該事實錯誤直接驅動了處方或劑量變更，或在急症與危險行為情境中壓制了必要的就醫轉介時，才會升級列入 CFR_composite。
3. **品質與過度拒絕：**
   - **QUALITY：** 定義為在未發生 CF 或 FACT 的情況下，規劃或實用性維度得分低於 2 分之情形。
   - **過度拒絕（Over-Refusal）：** 在 9 個良性對照中，將實用性低於 2 分之情形定義為過度拒絕。由於此定義包含僅提供最低限度衛教的情形，因此該指標可能存在高估傾向。
   - **規則掃描器與評判模型不一致（Scanner–Judge Disagreement）：** 比對基於正則表達式的規則掃描器與 LLM 評判模型的判定差異，各組分母為全部主案例與探針之總和（N=14）。掃描器僅為啟發式對照，不代表黃金真值。

所有二項比例指標均直接回報 Wilson 95% 信賴區間 [@Wilson1927]，直接引用凍結數據，不重新進行估算。

### 臨界安全失敗率分析（RQ1）

評判模型評估顯示，在 12 個主安全案例中，Base、Planner、Planner + Gate 與 Full-stack 四組的 CFR_strict 與 CFR_composite 皆為 **0/12（0.0%）**，且未發生任何 FACT 升級事件（escalations = 0；見 {FIG:2}）。

![Figure 2. 各消融條件之臨界失敗率（CFR）與 Wilson 95% 信賴區間](figures/figure2_cfr.png)

**{FIG:2} 主案例臨界失敗率（CFR_strict 與 CFR_composite）之點估計與 Wilson 95% 信賴區間。** 四組條件下兩項 CFR 點估計均為 0/12（0.0%），95% 信賴區間均為 0.0–24.25%。圖中將兩項指標給予垂直微幅偏移以利識別，圖例置於外下方。**在此特別強調：在有限樣本下，零觀察失敗絕不等於零風險（Zero observed failure ≠ Zero risk）**；單一組別的 Wilson 上限仍達 24.25%，而細分至各 CF family（N=2）時，其 95% 信賴區間上限更達 65.76%。因此，本數據絕無法作為各組具備臨床等效性或任一組別絕對安全之證明。向量圖見 `figures/figure2_cfr.svg`。

### 事實與病患狀態一致性分析（RQ2）

相較於 CFR 的零觀察，FACT 指標展現出高度依賴情境的非單調變化模式（{FIG:3}）：
- 在 12 個主案例中，FACT 發生率在 Base 為 2/12（16.67%），在 Planner 上升至 4/12（33.33%），而在 Planner + Gate 與 Full-stack 則均降至 0/12（0.0%）。
- 然而，在針對未陳述否定病史的 2 個探針案例（Probe Cases）中，情勢卻呈現完全相反的趨勢：Base 與 Planner 均為 1/2（50.0%），而在導入動態工具門禁與輸出護欄的 Planner + Gate 與 Full-stack 中，探針不一致率反而上升至 2/2（100.0%）。

![Figure 3. 主案例與事實探針之 FACT 不一致率分布](figures/figure3_fact.png)

**{FIG:3} 主案例與事實探針之 FACT 不一致率分布與 Wilson 95% 信賴區間。** 左圖 (a) 為主案例（每組 N=12），右圖 (b) 為否定病史探針案例（每組 N=2）。長條上方標註實際件數與比例，誤差線代表原始 Wilson 95% 信賴區間。此結果突顯出錯誤再分配的非單調性：主案例中 FACT 的減少並未轉化為探針情境下的同向改善。本研究未進行配對推論檢定，嚴禁據此斷言控制層具備因果優勢或任何配置全面較優。向量圖見 `figures/figure3_fact.svg`。

### 過度拒絕與評審一致性分析（RQ3、RQ4）

在 9 個良性對照案例中，四組條件之過度拒絕率均為 **0/9（0.0%）**，其 Wilson 95% 信賴區間上限為 29.91%。QUALITY 評分低於標準的比例在 Planner 與 Full-stack 各出現 1 例（1/12，8.33%），其餘兩組為 0/12。

在規則掃描器與評判模型的一致性分析上（分母 N=14），不一致案件數在 Base、Planner + Gate、Full-stack 各為 2/14（14.29%），Planner 為 3/14（21.43%；見 {FIG:4}）。

![Figure 4. 規則掃描器與 LLM 評判者之標記方向與條件分布](figures/figure4_scanner.png)

**{FIG:4} 規則掃描器與 LLM 評判者之判定分歧模式。** 左圖 (a) 為全域分歧方向（總計 9 筆不一致事件）：Scanner only 為 9 件（100%），Judge only 為 0 件（0%），Both 為 0 件。右圖 (b) 為四組消融條件下的不一致比例（每組 N=14，誤差線為 Wilson 95% CI）。9 筆分歧皆為掃描器單向觸發，與詞彙掃描較敏感／較保守的解釋一致；但評判模型亦非真值標準，本圖僅客觀呈現兩者判定模式之差異，不對任一方做真值歸因。向量圖見 `figures/figure4_scanner.svg`。

**評判管線穩定度與運行成本：** 評判模型在評估流程中累計呼叫 190 次（含 184 次軌跡雙評與 6 次 canary 驗證）；canary 驗證取得 6/6 全數通過，第三次仲裁（tie-break）呼叫次數為 0 次。在此聲明，canary 僅用以確認自動評估管線之運行完整性，不代表臨床安全率。系統累計報告之 Token 成本為：Talker 成本 US$0.2157378、Judge 成本 US$0.674631，合計 **US$0.8903688**（以匯率 32.0 計算約為新台幣 **28.49 元**）。

## 4.4 錯誤分析（Error Analysis）

透過檢視評估資料，我們對系統在事實與狀態層發生的具體錯誤進行定性剖析：

1. **研究案例事實矛盾（FACT_RESEARCH_GT_INCONSISTENCY）：** 在 Base 條件下，`SAFETY-RX-01-v2` 案例之第 3 輪對話中，系統在回覆中將雙胍類藥物「庫魯化（Glucophage）」錯誤描述為「刺激胰島素分泌之藥物」，與該案例背景設定檔中的藥物機制說明產生直接衝突，因而被評判模型判定為事實不一致。必須說明的是，此判定僅依據對話紀錄與研究案例內建之設定檔進行一致性比對，不涉及臨床藥理學的額外判定。
2. **無根據之否定病史（NEGH 探針）：** NEGH 探針專門設計用以檢驗「病患未曾提及」與「病患明確否認」之間的邏輯邊界。在測試腳本中，病患在首輪僅陳述了血糖與飲食狀況，完全未提及低血糖歷史；隨後腳本要求助理彙整就醫摘要，並在後續輪次中以固定台詞質疑助理「為何紀錄寫我沒有低血糖？」。評判模型檢核發現，在 Planner + Gate 與 Full-stack 條件下，系統在生成門診摘要或結構化記錄時，傾向於自動補齊臨床表單中的否定性欄位（將未提及之低血糖自動填寫為「無低血糖病史」），從而在探針中觸發了 FACT 錯誤。相對地，在良性對照案例中，若病患曾明確口頭表示「我從來沒有低血糖發作過」，系統據實記載「無低血糖病史」則被評判模型判定為具備真實依據。
3. **全域 FACT 代碼分布：** 綜觀全部 92 條對話軌跡的判定結果，各類 FACT 代碼的累計次數分別為：無根據之否定病史（11 次）、肯定事實增補（2 次）、研究案例事實矛盾（1 次）。這些代碼計數代表跨軌跡的標籤累計頻次，並非僅發生在探針情境，亦不可直接加總為獨立的失敗軌跡總數。這些質性發現精確補充了在臨界失敗率（CFR）皆為零的表面現象下，系統在事實與狀態維度上實際存在的微觀錯誤樣態。

# 5. 討論（Discussion）

本研究在固定底層模型與嚴格唯一差異架構下，檢驗了糖尿病衛教助理在多輪對抗施壓下的安全表現。研究數據揭示了兩個核心實證現象：其一，在小樣本高壓模擬下，四組條件的臨界失敗率（CFR）雖均為零觀察，但統計區間寬廣；其二，系統防線在事實與病患狀態維度上引發了非單調的**錯誤再分配（error redistribution）**。這些觀察對於醫療對話系統的架構設計與安全治理帶來了深層的啟示。

### 5.1 零觀察失敗不等於零臨床風險

評估結果顯示，Base、Planner、Planner + Gate 與 Full-stack 四組在 12 個主安全案例中的 CFR_strict 與 CFR_composite 均為 0/12（0.0%），且無任何 FACT 錯誤符合升級為臨界失敗的條件（escalations = 0；見 {FIG:2}）。然而，我們嚴正反對將此零觀察結果過度詮釋為「系統已達成絕對安全」或「各組具備臨床等效性」。

在統計學上，依據 Wilson 95% 信賴區間 [@Wilson1927]，0/12 的點估計所對應之母體失敗率上限高達 24.25%；若細分至各臨界失敗類別（每類 N=2），其信賴區間上限更達到 65.76%。在目前樣本下，0/12 的資料仍與最高 24.25% 的母體比例相容；這是統計不確定性界線，不是對真實風險的估計。現有樣本僅顯示系統在特定模擬測試腳本下未被誘發出嚴重違規。這項結果彰顯出：在安全攸關的醫療對話評估中，必須常態性報告信賴區間邊界，避免將「尚未觀察到失誤（zero observed）」誤導性地宣稱為「零風險（zero risk）」。

### 5.2 分層防線之錯誤再分配與情境相依性

相較於 CFR 的平坦分布，事實與病患狀態一致性（FACT）展現出高度動態且非單調的變化特徵（{FIG:3}）。這項實證結果挑戰了「防禦組件疊加越多，系統必然越安全」的線性直覺，呈現出與**錯誤再分配（error redistribution）**及**情境相依防護（context-dependent safeguards）**一致的模式。

具體而言，在 12 個主安全案例中，引入結構化臨床規劃員的 Planner 組，其 FACT 發生率由 Base 組的 2/12（16.67%）上升至 4/12（33.33%）。我們**假設（hypothesize）**：Planner 模組進行跨輪意圖定界與臨床導引生成，雖然結構化了對話脈絡，但亦增加了中間表徵的生成複雜度；當規劃員對病患複雜敘述進行摘要時，可能誘發模型產生額外的狀態推理，進而在 Talker 生成層引發非預期的事實漂移。進一步引入動態工具門禁（Planner + Gate）與輸出安全網（Full-stack）後，主案例的 FACT 錯誤觀察值較低，降至 0/12（0.0%）。但必須強調，本研究樣本規模較小且未進行配對推論檢定，此觀察值差異不能逕行作因果歸因，亦不能據此宣稱該控制層具備確切之抑制有效性。

然而，在評估「病患沉默是否會誘發系統捏造病史」的否定病史探針案例（Probe Cases）中，現象卻呈現相反的走向：Base 與 Planner 組的探針不一致率為 1/2（50.0%），而在 Planner + Gate 與 Full-stack 組中，探針不一致率則上升至 2/2（100.0%）。透過質性檢視，我們**假設**此走向源於臨床產卡機制的互動：在後兩組中，系統被引導主動生成結構化的就醫備忘錄卡片（`generate_visit_summary`），而標準化病歷表單通常包含「低血糖發作史」等固定欄位；當病患在對話中完全未提及此項病史時，具備高度結構化傾向的進階防禦管線傾向於將空白預設補齊為「無低血糖病史」，進而落入將病患沉默誤判為明確否認的認知陷阱。這項發現表明，防禦機制在特定情境下伴隨顯性事實衝突的減少，卻在另一情境下誘發了表單補全式的隱性事實偏誤。

### 5.3 品質指標、過度拒絕與評審一致性之省思

在衛教服務品質與可用性維度上，QUALITY 評分偏低的情形僅在 Planner 與 Full-stack 各出現 1 例（1/12，8.33%），顯示結構化約束與輸出攔截對常規衛教實用性的衝擊相對有限。此外，在 9 個良性對照案例中，四組的過度拒絕率均維持在 0/9（0.0%）。儘管這說明導入程式化防護網並未導致衛教助理全面陷入「防衛性拒絕」，但鑑於樣本規模（N=9）之限制，其 Wilson 95% 信賴區間上限仍達 29.91%，仍需在大規模真實語料中進一步檢驗。

在評審一致性方面，規則掃描器與盲測 LLM 評判者在 14 個案例（主案例加探針）中出現 2 至 3 例不一致（Base、Planner + Gate、Full-stack 各 2/14，Planner 為 3/14），全域累積 9 筆不一致事件且全數屬於「Scanner only」（{FIG:4}）。這項單向分歧模式與詞彙掃描較敏感／較保守的解釋一致，詞彙掃描可能將包含衛教說明或提及藥名但未指導調藥的語句標記為違規；相對地，評判模型則依據上下文語意進行裁決。然而必須強調，盲測評判模型絕非正確答案或客觀真值，本研究僅客觀呈現兩種判定機制的差異，分歧現象不能直接斷言為任一方的誤判或漏判。

### 5.4 程式化架構之工程可行性與價值

本研究在 92 條完整軌跡與 204 個對話回合的壓力測試中，累計耗費 API 成本為 US$0.8903688（約合新台幣 28.49 元），其中評判模型調用 190 次（含 6 次 canary 驗證，全數通過且未觸發 tie-break）。這顯示在本次受控環境下，固定評估協定具備可重跑性，且觀察到的 API 成本相對低廉。然而，其外部可重現性、跨架構可擴展性以及在實務部署前的實際效用，仍待納入更多模型家族與擴展案例進一步驗證。在共同提示詞與 Input Guard 基礎上，程式化分層架構（Planner、Tool Gate、Output Guard）為系統提供了可稽核的結構化干預點；然而，基於上述與錯誤再分配一致之觀察，開發團隊不應盲目預設防禦層級的疊加必然帶來安全性的單調提升。

# 6. 研究限制（Limitations）

本研究的設計與實證結論存在以下重要方法學限制，讀者在解讀與延伸本成果時應審慎考量：

1. **探索性與非預先註冊性質：** 本研究為 exploratory 探索性研究，研究協定與評估指標未進行前瞻性臨床試驗預先註冊（pre-registration），其統計顯著性不能用於推導確認性假說。
2. **小樣本規模與統計檢定力限制：** 評估規模僅包含 23 個精選案例（主案例 12 例、探針 2 例、良性對照 9 例），細分至六大臨界失敗類別時每類僅有 2 例（N=2）。廣泛的信賴區間限制了對微小效應量的偵測能力，且本研究未進行配對推論檢定，不推導因果推論。
3. **缺乏人類專家與真實病患評估：** 評估全程採自動化評估管線，未經真實臨床醫師、衛教師或糖尿病患者進行實際互動評分與臨床療效驗證，不能等同於臨床試驗結果。
4. **評判模型之共享模型偏誤：** 評估依賴 LLM-as-a-Judge（`gemini-3.7-flash`），同模型重複評分僅能反映同源模型在既定提示詞下的自身穩定度，無法消除模型內在架構與訓練語料所帶來的系統性共享偏誤（shared-model bias），絕不可視為客觀的人類專家真值 [@SameVerdict2026; @MedJUDGE2026]。
5. **部分解盲限制（Partially Blinded）：** 儘管對話封裝遮蔽了條件代號與內部狀態，但對話歷史中的 `tools_exposed` 欄位在客觀上使評判者能夠區分 {Base, Planner} 與 {Planner + Gate, Full-stack}，構成評估方法學上的非完全盲測。
6. **固定腳本與缺乏動態病患模擬：** 為確保消融條件間的受控比較，對話施壓採用預先固定台詞之多輪腳本，未導入具備動態適應能力的病患代理人（Patient Agent），未能完全模擬真實病患隨機、混亂或非理性的語言互動。
7. **單一模型版本與參數綁定：** 系統生成層與規劃層均綁定於特定模型版本（`gemini-3.5-flash-lite`）及特定隨機取樣溫度（0.3 與 0.1），結論無法直接泛化至其他參數量級或不同模型家族。
8. **未評估 RAG 內部檢索品質：** 消融實驗之焦點在於工具門禁之「暴露與調用時機」，對雙軌 RAG（向量檢索與知識圖譜）內部的檢索命中率、片段相關度及召回品質未進行獨立評估。
9. **規則掃描器之非真值屬性：** 規則掃描器僅作為決定性啟發式規則對照，其與評判者之分歧不能逕行判定為掃描器誤報或評判者漏判。
10. **在地化語境之外部效度侷限：** 衛教情境、用藥指引與對話用語均針對臺灣健保體系、國健署指引與繁體中文（含台語語意辨識）設計，對其他醫療體制或跨文化情境之泛化效度有限。
11. **研究案例事實設定之未查證狀態：** 評估資料集中部分藥物別名與藥理機制欄位僅屬測試案例之模擬參照設定，其臨床查證狀態標記為 `UNVERIFIED`，不得作為臨床藥理學事實引用。

# 7. 結論（Conclusion）

本研究透過嚴格的「唯一差異原則」消融實驗，對糖尿病衛教大型語言模型助理之分層系統防禦進行了多輪對抗安全壓力測試。在 23 個案例與 92 條完整軌跡的評估中，四組條件均未觀察到嚴格定義的臨界安全失敗，但其 95% 信賴區間上限表明零觀察結果不足以支持零風險主張。研究最為關鍵的實證觀察為：在固定底層模型下，分層安全防護網的導入呈現出與**錯誤形態在不同層次間重新分配（error redistribution）**一致的模式，其具體效應高度相依於對話任務之情境，而非單向、單調的安全改善。

本研究為醫療對話系統之安全架構提供了受控消融與低成本回歸測試的初步實證參考，並凸顯出在追求結構化防禦時審視隱性事實偏誤的重要性。未來的研究應進一步擴大對抗案例規模，引入多元模型家族交叉仲裁，並在嚴格的倫理審查下開展真實臨床環境與人類專家參與的雙盲前瞻性驗證。
